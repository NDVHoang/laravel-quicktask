# Chapter 1–2: Laravel Foundation, Migration and Model

## Chapter 1

### Các cách tạo Laravel project

Có nhiều cách để khởi tạo một dự án Laravel:

1. Thông qua Composer: `composer create-project laravel/laravel ten_du_an`
2. Thông qua Laravel Installer: `laravel new ten_du_an`
3. Cài đặt kèm Starter Kit (như dự án này sử dụng Blank React Starter Kit với Inertia, Vite, Tailwind CSS).

### Vai trò của `.env`

`.env` (Environment) là file chứa các cấu hình môi trường cụ thể cho từng nơi cài đặt (như Local, Staging, Production). Nó lưu trữ thông tin nhạy cảm như cấu hình cơ sở dữ liệu, API keys, thiết lập mail. Đặc biệt, `.env` không bao giờ được commit lên Git để đảm bảo an toàn bảo mật.

### Vai trò của APP_KEY

`APP_KEY` là một chuỗi ngẫu nhiên 32 ký tự, được Laravel sử dụng để làm "chìa khóa" mã hóa (encryption) cho các dữ liệu quan trọng như cookies, sessions và token. Nếu không có hoặc thay đổi `APP_KEY`, toàn bộ session hiện tại của hệ thống sẽ không còn hợp lệ.

### Mục đích các thư mục chính

- **`app/`**: Chứa toàn bộ core logic (Model, Controller, Middleware).
- **`bootstrap/`**: Khởi động framework và chứa file cache giúp tối ưu hiệu năng.
- **`config/`**: Nơi lưu trữ tất cả file thiết lập cấu hình của dự án.
- **`database/`**: Chứa Migrations (thiết kế schema), Seeders và Factories (dữ liệu mẫu).
- **`public/`**: Thư mục "mở" duy nhất ra bên ngoài, chứa file `index.php` (điểm bắt đầu của ứng dụng) và các tài nguyên tĩnh (assets) như CSS, JS.
- **`resources/`**: Chứa các file giao diện chưa qua biên dịch (Views, Vue/React component, SCSS, v.v.).
- **`routes/`**: Nơi định nghĩa tất cả các đường dẫn (URL) của ứng dụng.
- **`storage/`**: Chứa các tệp mà Laravel tự động sinh ra như Logs, Caches, Sessions, và files tải lên.
- **`tests/`**: Chứa các bài test tự động (Pest hoặc PHPUnit).
- **`vendor/`**: Chứa tất cả thư viện bên thứ 3 của Composer. Code ở đây tuyệt đối không được chỉnh sửa.

### Vòng đời request Laravel (Request Lifecycle)

1. Request từ người dùng đi vào **Web Server** (Nginx/Apache), sau đó được chuyển hướng đến file **`public/index.php`**.
2. **`index.php`** nạp autoloader và bootstrap ứng dụng qua **`bootstrap/app.php`**.
3. Request được đưa qua **HTTP Kernel**, đi qua các lớp bảo vệ **Middleware** (ví dụ: kiểm tra đăng nhập, CSRF).
4. Request tiếp tục đến **Router** để tìm kiếm **Controller** tương ứng.
5. **Controller** xử lý logic, có thể tương tác với **Model** để làm việc với DB, rồi trả về **View** hoặc **JSON** để tạo thành **Response** hoàn chỉnh gửi lại trình duyệt.

## Chapter 2

### Migration là gì?

Migration giống như hệ thống quản lý phiên bản (version control) cho cơ sở dữ liệu. Nó cho phép team dễ dàng chỉnh sửa, chia sẻ và theo dõi sự thay đổi của cấu trúc (schema) cơ sở dữ liệu qua các file code PHP thay vì phải sửa thủ công bằng mã SQL.

### Vai trò của `up()` và `down()`

- **`up()`**: Dùng để thêm bảng mới, cột mới, hoặc chỉ mục (index) vào cơ sở dữ liệu khi chạy `migrate`.
- **`down()`**: Dùng để hoàn tác (rollback) chính xác những thao tác mà hàm `up()` đã làm. Đảm bảo database có thể quay ngược lại trạng thái trước đó một cách an toàn.

### Các lệnh Migration thường dùng

- `php artisan make:migration [name]`: Tạo một file migration mới.
- `php artisan migrate`: Thực thi tất cả các migration đang ở trạng thái pending.
- `php artisan migrate:status`: Kiểm tra trạng thái của tất cả các file migration.
- `php artisan migrate:rollback`: Hoàn tác (chạy hàm `down()`) của lô (batch) migration gần nhất.
- `php artisan migrate:reset`: Hoàn tác toàn bộ tất cả migration về trạng thái ban đầu.
- `php artisan migrate:refresh`: Hoàn tác toàn bộ (Reset) và sau đó chạy lại lệnh migrate.
- `php artisan migrate:fresh`: Xóa sạch toàn bộ các bảng trong database bằng lệnh DROP và chạy lại migrate từ đầu.

> **⚠️ Cảnh báo**: Lệnh `migrate:fresh` sẽ **XÓA TOÀN BỘ BẢNG**. Tuyệt đối không dùng trên môi trường production nếu không muốn mất toàn bộ dữ liệu.

### Mass assignment là gì?

Mass Assignment là tính năng của Eloquent Model cho phép lưu hoặc cập nhật nhiều cột cùng lúc vào model thông qua một mảng (array), ví dụ `$model->fill($array)` hoặc `Model::create($array)`.
Tuy nhiên, nếu không kiểm soát, người dùng có thể nhồi thêm dữ liệu độc hại (như `is_active=1` hay `role="admin"`) thông qua form request để trục lợi.

### So sánh whitelist và blacklist

- **Whitelist (`$fillable` / `#[Fillable]`)**: Khai báo danh sách các cột **được phép** mass assignment. Các cột còn lại sẽ bị Framework chặn lại.
- **Blacklist (`$guarded`)**: Khai báo danh sách các cột **bị cấm** mass assignment. Các cột không nằm trong danh sách sẽ được phép điền hàng loạt.

### Vì sao dự án chọn whitelist?

Dự án ưu tiên sử dụng **whitelist** thông qua cú pháp `#[Fillable]` (Attributes của PHP 8) vì mang lại sự **an toàn mặc định**. Bằng cách chỉ định đích danh những trường an toàn được phép cập nhật hàng loạt, chúng ta không sợ bỏ sót những trường nhạy cảm mỗi khi thêm cột mới vào cơ sở dữ liệu.

### Cách cập nhật thuộc tính nằm ngoài whitelist

Đối với các trường nhạy cảm như `role`, `is_active` hoặc khóa ngoại `user_id`, ta cần gán thủ công từng thuộc tính vào Model thay vì gán qua mảng:

```php
$user = new User();
$user->name = 'Hoang';
$user->email = 'test@example.com';
$user->role = 'admin'; // Cập nhật thủ công một cách an toàn
$user->save();
```

### Schema thực tế của `users` và `tasks`

**Bảng `users`**:

- `id` (bigint, PK)
- `name` (string)
- `email` (string, unique)
- `password` (string)
- `role` (string, max: 20, default: 'user')
- `is_active` (boolean, default: true)
- `email_verified_at`, `remember_token`, `timestamps`

**Bảng `tasks`**:

- `id` (bigint, PK)
- `user_id` (foreign key trỏ đến `users.id`, xóa cascadeOnDelete)
- `title` (string, required)
- `description` (text, nullable)
- `status` (string, max: 20, default: 'pending')
- `due_date` (date, nullable)
- `timestamps`

### Danh sách lệnh dùng để kiểm tra Chapter 1–2

- Kiểm tra trạng thái hệ thống: `php artisan --version`, `php artisan about`
- Tạo Model & Migration: `php artisan make:model Task -m`
- Tạo Migration sửa bảng: `php artisan make:migration add_role_and_is_active_to_users_table --table=users`
- Chạy Migration: `php artisan migrate`, `php artisan migrate:fresh`
- Kiểm tra CSDL: `php artisan migrate:status`, `php artisan db:table users`, `php artisan db:table tasks`
- Format code: `./vendor/bin/pint`
- Chạy test tự động (Pest): `php artisan test tests/Feature/Models/TaskModelTest.php`
